# AI 智能旅行助手网站体验、功能逻辑与页面设计优化方案

> 文档版本：V1.0  
> 编写日期：2026-11-20  
> 评审对象：`http://localhost:5173/` 当前工作区版本  
> 文档性质：产品体验优化、交互逻辑设计、页面视觉设计与实施验收方案  
> 适用端：桌面 Web、平板、移动端 PWA

## 1. 文档目的

本方案不重写现有技术架构，也不把已经完成的 PWA、地图、RAG、Agent、离线缓存和质量门禁重复列为“待建设”。目标是在现有完整旅行闭环上，解决以下四类问题：

1. 用户是否能快速理解产品，并完成“规划、确认、执行、回顾”主流程。
2. 异步请求、Agent 流式执行、失败恢复和写操作是否具备正确且可解释的逻辑。
3. 桌面端和移动端是否有清晰的信息层级、稳定布局与一致交互。
4. 页面视觉是否符合“安静、可靠、任务导向的旅行工作台”定位。

本方案优先处理正确性和核心流程，再处理页面重构与视觉统一。不能用视觉改版掩盖重复写入、状态错误、失败回滚缺失或移动端不可用等问题。

## 3. 核心结论

当前最大的体验问题不是“功能少”，而是“功能很多，但主次、状态和责任边界不够清楚”。具体表现为：

1. 首页同时承载 AI 输入、四项统计、足迹、待办、Agent 运行、最近行程、待确认方案、提醒、日程和快捷入口，首屏没有回答“我现在最该做什么”。
2. 普通旅行用户功能与开发者诊断功能混在一级导航中，`Agent 运行观察`、任务 DAG、工具调用和技术术语过于前置。
3. “一句话规划”跳转到结构化表单后，没有解析并回填目的地、天数、人数和预算，用户仍需重复输入。
4. 移动端旅行列表会把较长标题压成逐字换行，属于核心页面的阻断性布局问题。
5. 移动端行程详情先展示地图和完整 AI 面板，用户需要长距离滚动才能看到“下一项安排”。
6. “旅行回顾”页面包含未来行程；“当前行程”页面又包含大量已结束行程，页面名称与内容范围不一致。
7. Agent 运行可显示整体“成功”，同时存在“研究步骤预算耗尽”和工具失败，用户无法判断结果是否完整可靠。
8. 首页和旅行列表把接口失败降级成 `0` 或“暂无数据”，错误与真实空状态混淆。
9. URL 中的 `q` 参数可能在刷新时重复执行写入类命令，存在重复创建备忘或日程的风险。
10. 当前设计令牌具备基础，但全局样式已超过 6000 行，Emoji、Ant Design 图标、不同圆角和历史覆盖规则混用，维护成本高。

## 4. 目标产品体验

### 4.1 产品定位

将产品定义为：

> 一个覆盖行前规划、行中执行、行后回顾的 AI 旅行工作台。AI 负责理解、建议和协助修改，用户始终能看见当前状态、影响范围和下一步动作。

### 4.2 设计原则

| 原则 | 设计要求 |
|---|---|
| 下一步优先 | 每个页面首先回答“用户此刻要做什么”，不是展示所有能力 |
| 状态真实 | 加载、空、失败、离线、部分成功、待确认必须视觉和语义分离 |
| AI 可解释 | 展示结论、影响和待核实项；技术运行细节默认折叠 |
| 写入可控 | 写操作幂等、可撤销、可重试；高影响操作先确认 |
| 移动先行 | 行中场景默认服务手机，下一项安排优先于地图和聊天 |
| 渐进披露 | 初次规划只问必要信息，高级偏好和诊断信息按需展开 |
| 视觉克制 | 减少卡片嵌套、Emoji 导航、渐变和无意义装饰 |
| 无障碍默认 | 语义控件、键盘操作、焦点环、对比度和 44px 触控目标作为验收项 |

## 5. 问题优先级与决策

### 5.1 P0：正确性与核心可用性

| 编号 | 问题 | 影响 | 方案 | 验收标准 |
|---|---|---|---|---|
| P0-01 | `q` 查询参数刷新后可能重复执行写入命令 | 重复备忘、日程或费用记录 | 使用 POST SSE；客户端生成 `requestId`；服务端按 `(userId, requestId)` 幂等；自动发送前消费 URL 参数 | 刷新、前进后退、弱网重连均只写入一次 |
| P0-02 | Agent 旧流回调可能覆盖新会话，过程错误又被当作终止错误 | 过期结果串页、错误解锁输入、错误跳转 | 每个 event/complete/error 校验流序号；拆分 warning 与 terminal error；开始新流时原子取消旧流 | 旧流任何晚到事件均不能改变当前 Store |
| P0-03 | 移动端行程列表长标题逐字换行，操作区挤压内容 | 390px 下核心列表不可扫读 | 行程卡改为上下两层；主链接独占一行；状态与金额次行；操作收进菜单 | 320px 起无横向滚动，标题最多两行，操作不挤压标题 |
| P0-04 | 加载失败与真实空数据混用 | 用户被误导为“没有数据” | 所有核心资源采用 `idle/loading/success/empty/error/offline-stale` 状态 | 500 或断网时不显示 0 和“暂无”；均有局部重试 |
| P0-05 | 核心可点击区域使用 `div/span/a`，缺少键盘语义 | 键盘和辅助技术用户无法完成任务 | 导航改 `NavLink`，动作改 `button`，列表采用主链接加独立菜单 | 仅键盘可完成登录、规划、确认、打开行程、记账和退出 |
| P0-06 | 三级文字颜色不满足正常文本 WCAG AA | 浅色和暗色辅助信息难读 | 浅色 `--text-3` 至少调整为 `#6b7280`，暗色至少调整为 `#8992a3` | 正常文本对比度不低于 4.5:1 |
| P0-07 | 总状态“成功”与工具失败、研究未完成并存 | 用户错误信任不完整方案 | 增加 `PARTIAL_SUCCESS` 和“待核实项”；总状态由模块结果聚合 | 任一必要模块失败时不能显示无条件“成功” |

### 5.2 P1：主流程与信息架构

| 编号 | 问题 | 方案摘要 |
|---|---|---|
| P1-01 | 首页信息过载 | 只保留全局输入、下一次旅行、今日任务和待处理事项；诊断和完整统计移出首页 |
| P1-02 | 一句话输入与表单断层 | 先解析自然语言并回填字段，只询问缺失或低置信信息 |
| P1-03 | 规划表单过长 | 改为三步流程，桌面显示吸顶摘要，移动端固定下一步按钮，自动保存草稿 |
| P1-04 | 移动端行程详情顺序不符合现场使用 | 改为“行程 / 地图 / AI”分段视图，默认行程，顶部显示下一项 |
| P1-05 | 行程详情页头操作过载 | 一级仅保留与当前阶段相关操作，回顾、路书、预算分析、撤销进入更多菜单 |
| P1-06 | 发送按钮看似可停止，实际禁用 | 实现真正的“停止生成”，或在未支持取消前不展示关闭图标 |
| P1-07 | 取消待确认方案失败时前端仍丢失方案 | 服务端成功后再清除，或失败回滚并保留 `planId` |
| P1-08 | 快速切换行程可能被旧响应覆盖 | 以 `tripId + requestSeq` 或 query key 隔离请求，并取消旧请求 |
| P1-09 | “旅行回顾”包含未来行程 | 默认仅显示进行中和已结束；未来行程放“准备中”，不提供“查看回顾”主动作 |
| P1-10 | “当前行程”混入全部历史行程 | 改名“我的行程”，并提供“待确认 / 即将出发 / 进行中 / 已结束”筛选 |
| P1-11 | 普通导航暴露开发诊断 | Workbench 迁入“设置 > 诊断”，普通用户不显示 DAG、模型额度和内部错误类名 |
| P1-12 | E2E 数据污染演示列表 | 测试使用隔离用户或执行后清理；UI 对测试数据增加环境隔离 |

### 5.3 P2：视觉一致性与工程维护

| 编号 | 问题 | 方案摘要 |
|---|---|---|
| P2-01 | Emoji 和 Ant Design 图标混用 | 核心导航、标题和工具按钮统一 Ant Design 图标；Emoji 仅用于对话或情绪表达 |
| P2-02 | 圆角、阴影和卡片层级不一致 | 控件 6px、普通卡片 8px、弹窗 10px；禁止卡片内再套装饰卡片 |
| P2-03 | `global.css` 超过 6000 行并依赖尾部覆盖 | 拆分 shell、home、planner、travel、trip、assistant、review；逐步采用 CSS Modules |
| P2-04 | 暗色首页仍强制浅色足迹地图 | 使用主题自适应地图或暗色遮罩，避免大面积高亮眩光 |
| P2-05 | `/ui-demo` 在生产路由可访问 | 仅开发环境注册，或迁移至独立组件预览环境 |
| P2-06 | Ant Design `InputNumber.addonAfter` 已废弃 | 改用 `Space.Compact`，清除当前浏览器控制台警告 |

## 6. 目标信息架构

### 6.1 普通用户导航

桌面侧栏：

| 一级入口 | 内容 |
|---|---|
| 首页 | 当前最重要任务、下一次旅行、今日安排、待处理事项 |
| 我的行程 | 待确认、即将出发、进行中、已结束、已取消 |
| AI 助手 | 通用对话、修改行程、问答、记录类指令 |
| 旅行资料 | 攻略库、备忘、记账、照片、回顾 |
| 我的 | 个人资料、提醒、外观、离线状态、诊断入口 |

固定主动作：`+ 新建行程`，不占用普通导航分组。

移动端底栏：

| 位置 | 入口 | 说明 |
|---|---|---|
| 1 | 首页 | 当前任务 |
| 2 | 行程 | 行程列表和当前行程 |
| 3 | 助手 | AI 对话 |
| 4 | 我的 | 资料、提醒、设置和更多工具 |

主题切换不再占用 20% 的移动一级导航，迁入“我的 > 外观”。

### 6.2 高级与内部入口

- `Agent 运行观察` 更名为“运行诊断”，迁入“我的 > 设置 > 诊断”。
- 任务 DAG、工具参数、Java 异常名默认只对开发或管理员角色开放。
- `/ui-demo` 仅开发环境开放。
- 知识库面向普通用户时更名为“攻略库”，隐藏“切块、文档 ID、Planner 研究链路”等内部术语。

### 6.3 路由建议

现有路由可以保留，先调整导航和文案，降低迁移风险：

```text
/
/travel
/planner
/trip/:id
/assistant
/resources            -> 聚合 expenses / memos / knowledge / review
/profile
/settings/diagnostics -> workbench
```

旧路径继续重定向，避免收藏链接和 PWA 快捷入口失效。

## 7. 核心用户流程重构

### 7.1 新建行程主流程

```text
一句话或粘贴攻略
       |
       v
解析需求并标注置信度
       |
       v
只追问缺失/冲突字段
       |
       v
用户确认需求摘要
       |
       v
Agent 规划：进度 + 可停止 + 待核实项
       |
       v
方案预览：路线 / 预算 / 风险 / 来源
       |
       v
确认保存 -> 行程详情
```

交互要求：

1. 自然语言中识别出的目的地、天数、人数、预算和偏好自动填入表单。
2. 置信度高的字段默认确认，置信度低的字段高亮并说明原因。
3. 冲突示例：“两天游”与三个具体日期冲突时，必须让用户选择，不静默覆盖。
4. 生成期间显示用户语言的阶段，如“正在查天气”“正在优化路线”，不默认展示内部 agent 名。
5. 允许停止生成。停止后保留已填写需求和已获得的阶段结果。
6. 方案提交前显示影响摘要，不直接落库后再让用户寻找变化。

### 7.2 写入类 AI 指令

将智能指令分为三类：

| 类型 | 示例 | 默认行为 |
|---|---|---|
| 只读 | “上海周末会下雨吗？” | 直接回答 |
| 可撤销写入 | “记一下明天办签证” | 幂等执行，结果卡提供撤销 |
| 高影响写入 | “取消整个行程” | 展示影响范围，用户确认后执行 |

统一逻辑：

- 客户端每次命令生成稳定 `requestId`。
- 服务端对写入类命令按用户和 `requestId` 去重。
- 使用 POST SSE，用户消息不放 URL。
- 自动发送的临时参数必须在发送前通过 `replace` 消费，离页时取消定时器。
- 成功结果显示“完成了什么”和“如何撤销”，不能只显示自然语言回复。

### 7.3 行中执行流程

行中场景的核心不是浏览全部计划，而是完成下一项：

1. 打开行程后直接看到当前时间、下一项、距离、交通时间和天气风险。
2. 主动作根据状态变化：`开始` -> `完成`，次动作放入菜单：`跳过 / 改时间 / 替换 / 查看地图`。
3. 完成后自动滚动到下一项，并提供短时撤销。
4. 网络离线时允许本地记录操作，明确标记“待同步”；恢复后显示逐项同步结果。
5. 地图和 AI 是辅助视图，不应在移动端压在时间轴之前。

### 7.4 行后回顾流程

1. 行程完成后触发“生成回顾”，而不是让所有未来行程都进入回顾列表。
2. 回顾优先展示完成率、实际花费、实际路线、照片和关键事件。
3. AI 总结基于真实完成数据，区分“计划”与“实际”。
4. 无照片、无轨迹或无事件时使用一个统一空状态，不重复多个同义空卡。
5. 可从回顾生成“下次偏好”，经用户确认后写入个人旅行偏好。

## 8. 页面设计方案

### 8.1 全局壳层与导航

#### 当前问题

- 桌面侧栏普通用户功能和开发诊断混排。
- 移动底栏把主题切换作为一级入口。
- 核心导航使用 Emoji，视觉基线和尺寸受操作系统影响。
- 品牌、导航和部分卡片不是语义化链接或按钮。

#### 目标设计

- 桌面侧栏宽度保持约 232px，可折叠至 72px 图标轨道。
- 一级导航只显示用户任务，底部放头像、提醒和设置。
- `新建行程` 使用固定的主按钮，不再让用户在多个相似入口间选择。
- 当前页使用 `aria-current="page"`，图标按钮提供 Tooltip 和 `aria-label`。
- 移动底栏固定四项；所有目标至少 44 x 44px。

### 8.2 首页

#### 页面目标

首页只回答三个问题：

1. 我下一次旅行是什么？
2. 我今天需要做什么？
3. 我现在可以让 AI 帮我做什么？

#### 桌面布局

```text
+------------------------------------------------------------------+
| 问候 + 全局命令输入                                  + 新建行程   |
+------------------------------------------------------------------+
| 下一次旅行：上海 2 日游 | 1 天后出发 | 查看行程 | 查看准备清单   |
+-------------------------------------+----------------------------+
| 今天要做什么                        | 待处理                     |
| 09:00 上海 3 日游 Day 2             | 4 个方案待确认              |
| 下一项、提醒、备忘                   | 5 个提醒                    |
+-------------------------------------+----------------------------+
| 最近足迹与回顾摘要，按需进入完整页面                              |
+------------------------------------------------------------------+
```

#### 内容调整

- 提交失败后恢复提交能力，并提供“按原需求重试”。

- 提供最近会话列表，支持新建对话和继续对话。

- 流式执行时提供真正可用的“停止生成”。
- 过程默认显示用户语言进度，任务 DAG 和工具调用折叠在“查看运行详情”。
- 结果消息内嵌来源、影响范围、待确认内容和撤销入口。
- 每个行程详情绑定独立 conversation scope，避免不同页面串消息和焦点。

### 8.8 旅行回顾

- 默认只列出进行中和已结束行程。
- 未来行程不显示“查看回顾”，改为“查看准备”。
- 提供目的地、年份和完成状态筛选。
- 列表主动作只保留一个：完成后为“查看回顾”，进行中为“查看进度”。
- 回顾详情将“计划”和“实际”并列比较，避免把预算、路线或地点混为一组。
- 照片、轨迹、事件和总结缺失时使用一个统一原因说明和单一下一步 CTA。

### 8.9 日程与足迹

#### 日程

- “今天”不应在“全部日程”中重复出现，或将后者明确改为“后续日程”。
- 移动端新增日程改为底部抽屉，避免五个横向控件挤在一行。
- 删除操作放入行尾菜单；完成复选框使用真实 checkbox 语义。
- 旅行自动生成日程与用户手工日程使用来源标签区分。

#### 足迹

- 当前空状态左右区域重复展示“还没有足迹”和两个不同 CTA，应合并为一个主空状态。
- 未打卡时只显示说明和 `去当前行程`；没有任何行程时才显示 `规划第一次旅行`。
- 地图加载失败、定位缺失和真实空数据分别处理。
- 暗色主题使用适配底图，避免大面积浅色画布。

### 8.10 运行诊断

- 普通用户只看到“本次规划部分信息待核实”，以及具体受影响内容。
- 开发者视图再展示任务 DAG、工具名、耗时和脱敏参数。
- 总状态定义：`排队中 / 运行中 / 等待输入 / 部分完成 / 已完成 / 失败 / 已停止`。
- 工具失败但已回退成功时显示“已降级完成”，不能与完全成功共用同一绿色标签。
- 当前运行结束时间必须晚于最后一个提交任务时间；指标聚合逻辑需加一致性检查。

## 9. 状态与反馈设计

### 9.1 页面状态模型

所有核心资源使用统一状态：

```ts
type ResourceState<T> =
  | { status: 'idle' }
  | { status: 'loading'; previous?: T }
  | { status: 'success'; data: T }
  | { status: 'empty' }
  | { status: 'error'; message: string; retryable: boolean; previous?: T }
  | { status: 'offline-stale'; data: T; cachedAt: string };
```

不要继续以 `null` 同时表达“未加载、加载失败和没有数据”。

### 9.2 状态矩阵

| 场景 | 页面表现 | 主动作 |
|---|---|---|
| 首次加载 | 与真实布局一致的 Skeleton | 无 |
| 空数据 | 解释为什么为空，给一个明确下一步 | 创建或返回 |
| 局部失败 | 模块内错误，不清空其他成功模块 | 重试 |
| 页面级失败 | 错误页保留导航和返回入口 | 重试 / 返回 |
| 离线有缓存 | 显示缓存时间和“只读”标签 | 离线浏览 |
| 离线无缓存 | 说明必须联网的原因 | 重新连接 |
| 部分成功 | 显示已完成、未完成和影响范围 | 重试失败项 / 继续使用 |
| 冲突 | 展示当前版本和新版本差异 | 重新加载 / 合并 |
| 用户取消 | 明确“已停止”，保留输入和已获得内容 | 继续编辑 / 重试 |

### 9.3 Toast 使用边界

Toast 只用于短暂确认，不承载需要用户决策的信息：

- 适合：保存成功、已复制、已撤销。
- 不适合：页面加载失败、方案冲突、部分成功、离线状态、待确认方案。

## 10. Agent 与数据逻辑优化

### 10.1 SSE 与会话隔离

当前 `agent.ts` 把服务端 error 事件视为可继续等待，但 `agentStore.ts` 又把任何 `onError` 当作终止。建议统一事件协议：

```ts
type AgentStreamEvent =
  | { type: 'progress'; runId: string; stage: string }
  | { type: 'warning'; runId: string; code: string; message: string }
  | { type: 'needs_input'; runId: string; fields: MissingField[] }
  | { type: 'partial_result'; runId: string; data: unknown }
  | { type: 'complete'; runId: string; result: unknown }
  | { type: 'failed'; runId: string; error: AgentError }
  | { type: 'cancelled'; runId: string };
```

客户端规则：

- 保存 `activeRunId` 和 `streamSeq`。
- 每个回调先校验 run 和 seq。
- 新请求前取消旧连接。
- reset、离页和切换行程后，旧事件全部丢弃。
- 过程 warning 不解锁输入，也不显示为最终失败。

### 10.2 幂等与 HTTP 语义

- 写入类命令由 POST 承载，不使用带完整用户消息的 GET URL。
- `requestId` 由客户端创建并随重试复用。
- 服务端保存写入结果或去重记录，重复请求返回首次结果。
- URL 参数仅用于预填，不用于自动执行不可逆或写入动作。

### 10.3 乐观更新与回滚

- 待确认方案：服务端取消成功后再移除，失败时保留并提示重试。
- 行程状态：可乐观更新，但失败必须回滚到上一个状态。
- 日程完成和行程项完成：先显示“正在同步”；离线时进入待同步队列。
- 删除操作不做静默乐观删除，等待服务端确认后移除列表。

### 10.4 请求乱序与缓存

- 行程详情请求以 `tripId` 为缓存键。
- 路由变化时取消旧请求，或在提交结果前校验目标 ID。
- 预算、时间轴和地图可独立加载，但必须共享当前 trip 版本号。
- 冲突时展示“此行程已在其他位置更新”，不静默覆盖。

### 10.5 登出

- 点击登出后立即清除本地身份、短期票据和敏感缓存。
- 服务端注销作为 best-effort 请求执行，失败不恢复本地会话。
- 登出按钮有提交态，防止重复点击。
- 浏览器返回键不能重新进入受保护内容。

## 11. 视觉设计系统

### 11.1 视觉方向

关键词：安静、清晰、可靠、旅行感来自真实内容而非装饰。

- 主界面使用中性灰背景和白色/深色表面，品牌蓝只用于关键动作和选中状态。
- 绿色只表示成功，橙色表示提醒或待核实，红色表示风险和危险操作。
- 不以渐变、发光或大量彩色 Emoji 制造旅行感。
- 旅行感由目的地地图、真实地点缩略图、天气、路线和照片提供。
- 工具型页面避免大标题、营销式 Hero 和多层悬浮卡片。

### 11.2 颜色令牌

保留现有蓝色体系并提高文本可读性：

| 令牌 | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `bg` | `#F6F7F9` | `#0F1115` | 页面背景 |
| `surface` | `#FFFFFF` | `#161920` | 主表面 |
| `surface-2` | `#F9FAFB` | `#1B1F27` | 次表面 |
| `border` | `#E4E6EB` | `#333A46` | 边框 |
| `text` | `#111827` | `#E8EAEE` | 主文本 |
| `text-2` | `#4B5563` | `#AEB6C3` | 次文本 |
| `text-3` | `#6B7280` | `#8992A3` | 辅助文本 |
| `accent` | `#1F6FEB` | `#6EA8FF` | 主动作 |
| `success` | `#16803C` | `#4ADE80` | 成功 |
| `warning` | `#B45309` | `#FBBF24` | 待核实/提醒 |
| `danger` | `#C62828` | `#F87171` | 危险/错误 |

状态不能只靠颜色表达，必须同时有图标或文字。

### 11.3 字体与层级

| 层级 | 桌面 | 移动 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 24px / 700 | 22px / 700 | 32px |
| 区块标题 | 18px / 650 | 17px / 650 | 26px |
| 卡片标题 | 15px / 650 | 15px / 650 | 22px |
| 正文 | 14px / 400 | 14px / 400 | 22px |
| 辅助文本 | 12px / 400 | 12px / 400 | 18px |

- 不使用随视口宽度缩放的字号。
- 字间距保持 0。
- 数字使用等宽数字特性，方便预算和时间对齐。

### 11.4 间距与栅格

- 基础间距：4 / 8 / 12 / 16 / 24 / 32px。
- 桌面内容最大宽度：1180 至 1280px。
- 表单正文宽度：720 至 800px。
- 桌面 12 列，平板 8 列，移动 4 列。
- 页面区块使用留白和分隔线组织，不把每个区块都做成悬浮卡片。

### 11.5 圆角、边框和阴影

- 输入和按钮：6px。
- 普通卡片和工具面板：8px。
- 弹窗和抽屉：10px。
- 标签、筛选项和状态徽标可使用胶囊圆角。
- 默认使用 1px 边框；阴影只用于弹层和真正悬浮内容。

### 11.6 图标与按钮

- 核心导航、工具按钮和状态统一使用 Ant Design 图标。
- 导航图标 18 至 20px，按钮图标 16px。
- 熟悉图标可使用纯图标按钮，但必须有 Tooltip 和 `aria-label`。
- 命令型操作使用图标加文字，如“生成计划”“保存攻略”。
- 危险动作不常驻红色主按钮，放入更多菜单并二次确认。

### 11.7 卡片与列表

- 卡片只用于独立重复项、工具面板和弹层。
- 不在卡片内再嵌套装饰卡片。
- 列表行使用固定列约束，动态文字不得改变操作区尺寸。
- 长标题最多两行，使用省略和 Tooltip，不逐字折行。
- 空状态只提供一个主 CTA。

## 12. 响应式规则

### 12.1 断点

| 范围 | 布局 |
|---|---|
| `>= 1280px` | 完整侧栏，双栏或三栏工作台 |
| `1024-1279px` | 完整侧栏，主次双栏压缩 |
| `768-1023px` | 折叠侧栏或顶部导航，单栏优先 |
| `< 768px` | 四项底栏、单栏、底部抽屉和固定上下文动作 |

必须额外在 320、390、768、1024 和 1440px 验收，不只检查 CSS 断点附近。

### 12.2 移动端通用规则

- 可点击区域最小 44 x 44px。
- 页面底部 padding 包含底栏高度和 `safe-area-inset-bottom`。
- 不把超过三个输入控件排在同一行。
- 表格改为卡片或可展开行，不依赖横向滚动完成主要任务。
- 地图、图表和聊天使用稳定高度与 `aspect-ratio`，动态内容不能导致布局跳动。
- 主要按钮固定底部时不能遮挡表单最后一个字段。

### 12.3 行程列表专项规则

- 卡片主信息使用 `minmax(0, 1fr)`，操作区不得挤压标题。
- 390px 下主信息和操作区上下排列。
- 内部 `word-break` 使用正常中文换行，英文/编号采用省略，不允许每字符一行。
- 状态、日期、人数和预算按重要性逐级隐藏或换行，不缩小至不可读字号。

## 13. 无障碍要求

1. 所有导航使用链接，所有动作使用按钮。
2. 自定义控件必须支持 Tab、Shift+Tab、Enter、Space 和 Esc。
3. 当前导航、当前 Tab、选中筛选和展开状态提供 ARIA 属性。
4. 所有图标按钮有可访问名称和 Tooltip。
5. 焦点环统一为 2px 高对比轮廓，不被 `overflow` 裁切。
6. 正常文本对比度至少 4.5:1，大文本至少 3:1。
7. 状态不只靠颜色；地图路线和图表同时使用线型、标签或图标。
8. 表单错误与字段关联，提交后聚焦第一个错误并提供错误摘要。
9. 动效尊重 `prefers-reduced-motion`。
10. 屏幕阅读器能理解 Agent 进度，但进度播报节流，避免频繁打断。

## 14. 指标与埋点

### 14.1 北极星流程指标

| 指标 | 定义 | 目标方向 |
|---|---|---|
| 首次可用方案时间 | 从开始输入到出现可确认方案 | 降低 |
| 规划完成率 | 开始规划后成功进入方案确认的比例 | 提高 |
| 方案确认率 | 方案预览后确认保存的比例 | 提高 |
| 字段重复输入率 | 自然语言已有信息仍被手工重复填写的比例 | 接近 0 |
| 部分成功识别率 | 有失败模块时正确展示部分成功的比例 | 100% |
| 重复写入率 | 同一 requestId 产生多条记录的比例 | 0 |
| 移动行中动作完成率 | 打开行程后完成“开始/完成下一项”的比例 | 提高 |

### 14.2 体验与质量指标

- 320 至 1440px：无横向滚动、重叠和不可见操作。
- 自动化可访问性：0 个 critical，0 个 serious。
- Core Web Vitals 建议目标：LCP <= 2.5s、INP <= 200ms、CLS <= 0.1。
- 点击“停止生成”后 300ms 内恢复输入能力。
- 模块失败后 100% 提供可见重试或明确不可重试原因。
- 页面错误不得被统计为 0 或真实空状态。

埋点不得记录完整用户攻略、对话正文、精确位置或其他敏感内容；只记录事件类型、耗时、状态和脱敏错误码。

## 16. 测试与验收计划

### 16.1 必补自动化测试

#### 单元与 Store 测试

- `q` 只消费一次，卸载前定时器会取消。
- 同一 `requestId` 重放不重复写入。
- 旧 seq 的 event、complete、warning、failed 全部被忽略。
- 用户主动 abort 后晚到事件不改变状态。
- 取消方案 500 时恢复 `pendingConfirm`。
- 两个 trip 响应逆序时不会串数据。
- 登出接口失败时本地身份仍立即清除。

#### 组件测试

- 首页模块分别覆盖 loading、empty、error、offline-stale。
- 行程卡长中文、长英文和 `e2e-*` 标题不破坏布局。
- 规划器自然语言字段自动回填和低置信确认。
- 行程项在不同状态只显示一个主动作。
- 图标按钮均存在可访问名称。

#### E2E

1. 首页输入“记一下明天办签证”，进入助手后刷新，数据库只增加一条记录。
2. 快速切换两个行程，标题、地图和时间轴始终属于当前 ID。
3. Agent 生成中停止，输入区在 300ms 内恢复，结果显示“已停止”。
4. 工具调用失败但有降级结果时显示“部分完成”，并列出待核实项。
5. 模拟 404、500、429、断网和恢复，页面状态符合矩阵。
6. 在 390、768、1024、1440px 完成规划、确认、打开行程和完成下一项。
7. 仅键盘完成核心流程。

### 16.2 视觉验收

- 页面无文字溢出、遮挡、逐字竖排或横向滚动。
- 固定底栏和固定 CTA 不遮挡内容。
- 浅色和暗色均满足文本对比度。

## 18. 最终验收定义

本轮优化完成必须同时满足以下条件：

1. 用户从首页输入一句话后，不重复填写已识别信息即可生成方案。
2. 同一写入命令无论刷新、重连或重放都只执行一次。
3. 移动端打开行程后，首屏能看到下一项安排和主动作。
4. 320 至 1440px 不出现横向滚动、操作遮挡和标题逐字换行。
5. 失败、空数据、离线和部分成功在视觉与语义上明确区分。
6. 普通用户主导航不再暴露 Agent DAG、工具调用和内部技术术语。
7. 所有核心操作可仅用键盘完成，文本对比度达到 WCAG AA。
8. 首页首屏只有一个主任务，并且不超过三个高优先级信息块。
9. 旅行回顾不再把未来行程作为可回顾内容。
10. 全部自动化门禁通过，且保留 PWA、离线、地图和包体优化成果。

本方案建议先完成阶段 A，再开展视觉和页面重构。否则新页面仍会继承重复写入、异步串页、错误状态伪装为空数据等问题，改版后的界面也无法形成可信的旅行工作流。
