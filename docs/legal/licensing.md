## 2. 为什么没有直接选 MIT / Apache-2.0

开源许可证是**商业决策**，不是技术默认值。选择 MIT/Apache-2.0 会永久允许他人复制、修改、商用分发（Apache-2.0 另含专利授权与 NOTICE 要求），且很难撤回。当前仓库：

- 尚未完成第三方依赖许可证审计与 NOTICE 文件；
- 含商业数据源（高德、LLM）与运营配置，公开源码前需确认合同允许；
- 未确定商标、专利与贡献者协议策略。

因此本批只做**专有声明**，把“是否开源、用哪种许可证”留给业务与法务决定。不得为了“看起来完整”擅自改成本仓库未批准的许可证。

## 3. 切换到开源许可证的流程（业务决策）

> 触发条件：业务方书面决定开源（或双许可），法务完成评估。以下每一步都需要评审记录，不能只改一个文件。

1. **确定目标与范围**：整仓开源 / 仅后端或前端 / 双许可（开源 + 商业）；是否允许商用、是否要求署名、是否含专利授权。
2. **法务选择许可证**：MIT、Apache-2.0、AGPL-3.0 等适用场景不同（AGPL 对网络服务有额外源码提供义务）；由法务拍板，不由工程默认选择。
3. **替换 `LICENSE`**：写入完整许可证原文；在 `README.md`、`docs/legal/licensing.md` 同步说明；保留原专有声明作为历史记录（可在 `docs/CHANGELOG.md` 记录切换日期与决定人）。
4. **同步包元数据**：`travel-agent-web/package.json` 增加 `"license": "<SPDX-ID>"`；`travel-agent-server/pom.xml` 增加 `<licenses>`；如发布 npm 包/镜像，补充相应元数据。
5. **第三方合规审计**：
   - 逐项核对直接与传递依赖的许可证（Spring Boot、React、Ant Design、MapLibre、数据库驱动等），确认与目标许可证兼容；
   - 生成并提交 `NOTICE` / 第三方声明文件（含版权行与许可证文本）；
   - 处理不兼容依赖（替换、移除或调整许可策略）；
   - 确认高德/LLM 等**数据与 API 合同**允许开源客户端代码（服务本身仍受供应商条款约束）。
6. **清理敏感内容**：真实 Key、内部地址、未公开运营数据不得随开源泄露；`gitleaks` 全历史扫描（不只是当前 HEAD）。
7. **更新 CI 与文档**：许可证头检查（如需要）、README、`docs/guide/README.md`、隐私政策中的运营主体说明。
8. **发布记录**：切换 commit、法务意见、依赖审计结果、决定人、生效日期，与 [路线图](../PROJECT_ROADMAP.md) 的 P0-D 发布审批一并归档。

## 4. 贡献与再分发

- 当前不接受外部贡献；若开放贡献，需先确定 CLA/DCO 与贡献者许可，否则无法保证后续可再许可。
- 任何再分发（镜像、二进制、SaaS）在专有许可下都需要书面授权；获得授权时应在合同中写明范围、期限与责任限制。
- 本项目使用的第三方依赖仍受各自许可证约束；专有声明不改变这些依赖的许可义务（例如保留版权声明、NOTICE）。
