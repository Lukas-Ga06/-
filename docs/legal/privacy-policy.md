## 2. 我们收集哪些数据

当前数据模型中**没有**手机号、邮箱、身份证、精确支付账户等字段；账号只有用户名、昵称与密码哈希。若后续新增字段，必须同步更新本政策与删除流程。

| 类别 | 具体内容 | 存放位置 | 来源 |
| --- | --- | --- | --- |
| 账号 | 用户名、昵称、密码**哈希**（BCrypt）、创建时间 | 表 `users` | 用户注册或第三方渠道自动建号 |
| 行程 | 标题、目的地、起止日期、预算、同行人数、状态；每日行程项（标题、时间、费用、状态） | 表 `trip`、`itinerary_item`、`trip_event` | 用户输入或 AI 方案经用户确认后写入 |
| 记账 | 金额、类别、支付方式、时间、关联行程 | 表 `expense` | 用户输入或 Agent 写操作经确认后写入 |
| 备忘与日程 | 标题、内容、日期、完成状态 | 表 `memo`、`schedule_item` | 用户输入或确认后的 Agent 操作 |
| 照片 | 图片文件、原始文件名、类型、大小、关联行程与用户 | 表 `trip_photo`；文件在本地卷 `data/photos` 或 S3 兼容对象存储 | 用户上传 |
| 会话 | 消息正文、角色、会话 ID、页面归属、轮次序号、用户改过的会话标题 | 表 `conversation_message`、`conversation_meta` | 用户与 AI 对话 |
| Agent 运行与待确认方案 | 用户消息、意图、运行状态、任务摘要与错误、工具调用摘要（截断的 `args_digest`/`result_digest`）、待确认方案内容与指纹 | 表 `agent_run`、`agent_task`、`tool_call_trace`、`pending_plan`、`plan_execution`、`operation_history`、`agent_command_dedupe` | 系统运行产生 |
| LLM 用量 | 用户名、日期、当日调用次数 | 表 `llm_quota_usage` | 系统计量 |
| 个人知识库 | 用户保存的攻略标题、城市、正文、版本、向量块 | 表 `rag_document`（`user_id` 非空）、`rag_document_version`、`rag_chunk` | 用户保存 |
| 日志 | 时间、级别、消息、`traceId`；nginx 访问日志计划使用 `without_args` 格式只记请求方法与 `$uri`（不记查询串；配置位置需先修正，见 [Runbook 附录 A](../operations/runbook.md)）；应用侧 Redis fail-open WARN 仍可能含用户名/IP（已知缺口） | 容器 stdout（`docker compose logs`，10m × 3 轮转），保留由部署方决定 | 系统运行产生 |
| 登录凭证 | httpOnly Cookie `travel_agent_token`（JWT）；照片/SSE 使用 300 秒短期只读票据 | 用户浏览器；票据出现在 URL 查询串 | 登录时签发 |

**不收集**：仓库代码未集成任何第三方统计、广告或崩溃分析 SDK；没有读取通讯录、精确位置权限（地图坐标来自用户输入或所选 POI）。

## 3. 处理目的

| 目的 | 用到的数据 | 说明 |
| --- | --- | --- |
| 提供旅行规划与行程管理 | 账号、行程、记账、备忘、日程、会话 | 核心功能，不提供则无法使用 |
| 生成与调整 AI 方案 | 会话、行程摘要、工具观察结果、知识引用 | 需要调用第三方 LLM（见 [第三方服务说明](third-party-services.md)） |
| 地图、路线与天气 | 城市名/地址、POI 关键词、坐标 | 需要调用高德或 Open-Meteo；未配置时走本地估算/模拟 |
| 账号安全与限流 | 用户名、IP（限流键）、登录时间 | 防爆破、防滥用、保护模型成本 |
| 排障与审计 | 日志、Agent 追踪、操作历史 | 定位故障、支持撤销与问题复核 |
| 计费与配额 | 用户名、每日调用次数 | 防止单账号刷爆模型账单 |

## 4. 保留期

保留期以实现为准（配置项与默认值同样以 `application.yml` 为准）：

| 数据 | 保留期 | 依据 / 边界 |
| --- | --- | --- |
| 会话消息 | 默认 **7 天**（`CONVERSATION_RETENTION_DAYS`） | 写入侧快路径（每小时最多一次）+ 每日 04:30 定时清理 |
| 会话标题覆盖 | **无自动到期清理** | 仅在用户删除会话时一并删除；属已知保留缺口，见 [数据删除流程](data-deletion.md) |
| Agent 追踪（run/task/tool） | **14 天** | `AgentTraceService.RETENTION_DAYS`；每日 04:40 清理 |
| 待确认方案 | **30 分钟**（TTL） | 过期行在新方案写入时清理 |
| 知识库历史版本块 | 只保留最近 **2** 个历史版本（`RAG_CHUNK_VERSION_RETENTION`） | 版本行与正文保留，块由每日任务清理 |
| 行程、记账、备忘、日程、照片 | 保留至用户删除或账号注销 | 账号注销已实现：事务内删除本人数据，照片文件在提交后清理；**不可恢复** |
| 个人知识库 | 保留至用户删除或账号注销 | 账号注销会删本人文档/版本/块，公共知识（`user_id` 为空）保留；内存 RAG 索引刷新仍是待验证项 |
| LLM 用量计数 | 无自动清理 | 按用户名 + 日期长期保留，用于配额与审计；账号注销时按用户名删除 |
| 日志 | 由部署方决定；compose 为 `backend`/`web` 配置 10m × 3 轮转 | 应用未内置日志保留策略；生产需按部署配置并书面化（见 [生产配置清单](../operations/production-config.md)） |
| 备份 | 由运维保留策略决定 | 备份中的历史数据不会被“账号删除”自动清除，需在备份保留周期内自然过期；见 [备份/恢复](../operations/backup-restore.md) |

## 5. 第三方处理方

调用第三方时**只发送完成该功能所需的最少内容**：例如 LLM 收到用户消息、必要的行程摘要与工具观察；高德收到城市/地址/POI 关键词与坐标；天气服务收到城市或坐标。不会主动发送用户名、密码或登录 Cookie。

| 处理方 | 处理的数据 | 触发条件 | 详见 |
| --- | --- | --- | --- |
| DeepSeek 或其它 OpenAI-compatible LLM | 对话文本、行程摘要、提示词、工具观察摘要 | 配置了 `LLM_API_KEY` 且 `LLM_ENABLED=true` | [第三方服务说明](third-party-services.md) |
| Embedding 供应商（默认未启用） | 知识库正文、检索查询文本 | `EMBEDDING_ENABLED=true` | 同上 |
| 高德（REST / MCP / JS API） | 地址、城市、POI 关键词、坐标；前端地图请求 | 配置 `AMAP_KEY` / `AMAP_MAPS_API_KEY` / `VITE_AMAP_KEY` | 同上 |
| Open-Meteo | 城市名或坐标 | `WEATHER_REAL=true` | 同上 |
| S3 兼容对象存储（可选） | 照片文件与元数据 | `PHOTOS_STORE=s3` | 同上 |
| Redis（可选，通常为自建） | 限流计数键（含用户名或 IP、300 秒过期） | `RATE_LIMIT_STORE=redis` | 同上 |
| GitHub（代码托管与 CI） | 源代码、CI 构建日志；CI 当前未引用生产密钥 | 使用仓库 CI | 同上 |

跨境传输：是否发生跨境取决于所选供应商与部署地域（例如 LLM/Embedding/S3 的所在地）。**本仓库不对此作合规结论**，上线前需由法务确认并补充告知/同意机制与合同条款。

## 6. 用户权利与当前可执行的操作

| 权利 | 当前状态 | 用户可执行的方式 |
| --- | --- | --- |
| 查看账号信息 | **已实现** | `GET /api/auth/me`（页面个人中心） |
| 查看行程 / 记账 / 照片 / 会话 | **已实现** | 对应页面与列表接口 |
| 修改行程 / 记账 / 备忘 / 日程 | **已实现** | 页面编辑（受归属校验） |
| 删除行程（含行程项、账单、照片元数据、历史、事件、关联日程/备忘） | **已实现** | `DELETE /api/trips/{id}`；照片文件随删除清理 |
| 删除单张照片 | **已实现** | `DELETE /api/photos/{id}` |
| 删除会话 / 清空当前会话 | **已实现** | `DELETE /api/agent/conversations/{conversationId}`、`POST /api/agent/conversation/clear` |
| 导出个人数据（机器可读） | **未实现** | 仅可导出单行程 PDF 路书；无账号级导出接口 |
| 删除账号及全部关联数据 | **已实现** | 个人中心（`/profile`）→「危险区 · 注销账号」：输入当前密码 + 勾选“不可恢复”确认；成功 200 并清 Cookie。删除范围见 [数据删除流程](data-deletion.md) §2；**不可恢复** |
| 撤回同意 / 注销 | 可通过账号注销实现 | 注销即删除账号与本人数据；注销后无法用原账号登录，旧 JWT 在过期前仍能通过签名认证但业务接口返回 401（同名重注册的残余风险见 [数据删除流程](data-deletion.md) §3.1） |

> **发布前仍需完成**：账号删除已有 API 与 H2 测试，但**账号级数据导出未实现**；MySQL/S3/内存 RAG 与旧 JWT 同名重注册风险见 [数据删除流程](data-deletion.md) §8/§9。手工 SQL 只是兜底，不能替代产品能力。
>
> **留存例外**：日志、备份中的历史数据不会随账号删除立即消失，按保留周期自然过期；如法务/安全要求保留特定审计或安全日志，需明确类别、期限与访问权限（占位：`[需法务明确]`）。

## 7. 安全措施（现状）

| 措施 | 现状 |
| --- | --- |
| 密码存储 | BCrypt 哈希，不存明文 |
| 登录态 | httpOnly + `SameSite=Lax` Cookie；HTTPS 部署必须 `COOKIE_SECURE=true` |
| 资源访问 | 照片/SSE 使用 300 秒短期只读票据，按用途隔离；不能用于写接口 |
| 权限隔离 | 业务查询按 `user_id` 校验归属；个人知识库按 `user_id` 隔离 |
| 滥用防护 | 登录/上传/Agent/默认接口限流；LLM 每日配额 |
| 密钥管理 | 只从环境变量读取；仓库不保存真实 Key；CI 有 gitleaks 密钥扫描 |
| 传输 | 生产要求 HTTPS 终结；仓库内 compose 只监听 8081，需外层 TLS |

已知缺口（发布前需收口）：nginx 票据日志配置已修正为 `http` 上下文、仍待 `nginx -t` / 真实容器验证；应用侧 Redis fail-open WARN 仍可能带用户名/IP；账号注销的 MySQL/S3/内存 RAG 未实测，旧 JWT 在“注销后同名重注册”场景可能映射到新账号（无 token 版本/jti）；账号级导出未实现；日志保留期未书面化。
